# VFR OFP Builder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `ofp.html`, a page where a student clicks waypoints on the FAA TAC or sectional. The page computes the LAT VFR OFP by the B02 rules, checks MSA, airspace and glide reach, prints the OFP on the ATO form, exports a ForeFlight `.fpl`, and hands time and fuel to the T/O sheets.

**Architecture:**
- Plain browser scripts that also run as CommonJS, like `perf.js`. No build step.
- Pure maths lives in `nav.js` and `safety.js`, tested with `node test.js`.
- Network code lives in `ofpdata.js`. UI lives in `ofp.js`.
- Supabase RPCs own token charging. The PDF is drawn with pdf-lib onto the blank form.

**Tech Stack:** vanilla JS, Leaflet (vendored), pdf-lib and pdf.js (already vendored), WMM2025 (vendored), Supabase SQL, Vercel functions.

**Spec:** `docs/superpowers/specs/2026-11-24-vfr-ofp-design.md`

## Global Constraints
- No package.json, bundler or npm runtime dependency. Every new browser module is a classic script that ends with `if (typeof module !== 'undefined' && module.exports) module.exports = X; else root.X = X;`.
- Tests are added to `test.js` using its `eq(name, got, want, tol)` helper and `fail` counter. Run them with `node test.js`, which must end with no `FAIL` lines.
- Units:
  - distances in NM
  - altitudes in ft MSL
  - fuel in USG to 0.1
  - times as whole minutes
  - courses and winds **magnetic** in the OFP
  - clock times as `HHMM` strings
- B02 rules are the source of truth over the Excel sheet. Source PDFs are in `/Users/jonahmaikranz/Downloads/` (B02: `Doc_B0_2-SEP-26.pdf.pdf`; read it with the Read tool and `pages`).
- OFP price is **3 tokens**, a server constant. It is charged once per flight (same OFP id + flight_date + dep + dest).
- Automatic MSA, airspace and emergency-field outputs carry a visible "verify on chart" note.
- Commit after each task on branch `feature/vfr-ofp`. Message style: a short imperative sentence, like the existing log. End each commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push.

## Review Focus
1. **Courses that wrap through 360/000** (MC 358 to 002, wind from 010 on MC 350). Wind angle, WCA and the semicircular rule must treat this as a 4° difference, not 356°. Test in Task 1.
2. **Wind too strong for the triangle** (crosswind ≥ TAS, or GS ≤ 0). `windTriangle` returns `{error:'wind'}`. The UI shows the problem on that leg, and the PDF never prints `NaN`. Test in Task 1. The UI part is in Task 6.
3. **Data source down or offline** (ADDS, terrain, winds). The page still plans with manually entered MSA, wind and altitude. Each failed source is shown as "unavailable" and never as zero. The pure functions are tested with empty inputs in Task 5. The UI part is in Task 6.
4. **An ATO procedure whose point the admin hasn't placed yet** (no coordinates). The procedure is listed but disabled, with "not placed yet". Nothing crashes. Test `ATO.usable` in Task 3.
5. **Overflow:** more than 18 legs, or long waypoint names. The check warns at more than 18 legs. The PDF truncates names to the cell width and only prints the first 18 legs. Test `OfpPrint.layout` in Task 4.

**Interfaces:**
- Produces, as global `Nav` (all pure):
  - `dist(a, b) -> NM` and `brg(a, b) -> deg true 0–360`. Points are `{lat, lon}`.
  - `mid(a, b) -> {lat, lon}` and `along(a, b, frac) -> {lat, lon}`.
  - `offset(p, brgDeg, nm) -> {lat, lon}`.
  - `xtrack(p, a, b) -> NM`: distance from point `p` to segment a–b.
  - `norm360(d)` and `angDiff(a, b) -> -180..180`.
  - `variation(p, date) -> deg`, east positive, using `WMM.declination(lat, lon, altKm, decimalYear)` from `vendor/wmm.js`. In node, use `require('./vendor/wmm.js')`.
  - `magCourse(a, b, date) -> int`: true course at the midpoint minus east variation. **Check this sign:** MC = TC − E var, so TC 100° with 10°E gives MC 090.
  - `windTriangle({mc, tas, wdir, wspd}) -> {wca:int, hdg:int, gs:int} | {error:'wind'}`. `wdir` is magnetic, wind FROM. `hdg = norm360(mc + wca)`.
  - `eet(distNm, gs) -> int`, which is `ceil(dist/gs*60)`.
  - `climbAdd(fromFt, toFt) -> {min, gal}`.
  - `pattern({touchGo=0, taxiBack=0, fullStop=false, airwork=0}) -> {min, gal}`.
  - `msa(maxElevFt) -> ft`.
  - `tocNm(fromFt, toFt) -> NM` (105 kt, 500 fpm) and `todNm(cruiseFt, tpaFt) -> NM`.
  - `semicircularOk(mc, altFt, groundFt) -> bool`. True when `altFt - groundFt <= 3000`.
  - `semicircularAlts(mc, minFt, maxFt) -> [ft]`.
  - `glideReachNm(altFt, elevFt) -> NM`, which is `(alt-elev)/6076*9*0.8`, never below 0.
  - `computeOfp(input) -> log` (shapes below).
  - `fmtEet(min) -> ':05' | '1:05'` and `addHHMM('1006', 5) -> '1011'` (wraps past midnight).

`computeOfp` input:

```js
{ toTime:'1006', takeoffFuel:54.5, reserveMin:30, cruiseFf:12.7,
  rows:[ // rows[0] = first point after departure, last = destination
    { name, ident, lat, lon, alt, msa, mc, dist, wdir, wspd, tas, ff,
      fixed:{min,nm}|null,                                   // ATO procedure leg
      pattern:{touchGo,taxiBack,fullStop,airwork}|null,      // remarks at this point
      prevAlt }                                              // altitude flown into the leg from (for climb add)
  ] }
```

Output:

```js
{ rows:[{ ...input row, wca, gs, eet, pto, legFuel, plFuel, minFuel, climb:{min,gal},
          extra:{min,gal}, how:{wca,gs,eet,legFuel,plFuel,minFuel}, error? }],
  totals:{ eet, trip }, reserveGal }
```

`how` strings show the working, for example `"8 NM / 147 kt = 3.3 → :04"`.
